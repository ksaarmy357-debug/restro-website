## 2026-07-26 - Accessible Accordion Headers & Interactive Controls
**Learning:** Placing a heading inside an interactive button element is invalid HTML since buttons must only contain phrasing content. For fully accessible components, the correct structure is wrapping the button inside the heading (`<h3><button type="button">...</button></h3>`). Additionally, when using dynamic third-party icon libraries like Lucide that replace `<i>` tags with `<svg>` elements on rendering, CSS transition selectors must target both elements (e.g., `i` and `svg`) to preserve smooth animations like rotating indicators.
**Action:** Always wrap interactive button controls in heading elements rather than nesting headings inside buttons, target both `i` and `svg` selectors for visual animations of dynamic icons, and explicitly define focus-visible states using high-contrast colors (like `var(--accent-amber)`) with offset adjustments when custom pointer overlays block standard outlines.
